# 本地检索与批量验收

工作台现支持使用真实嵌入 API 建立本地知识索引，并依据命中的知识卡回答问题。索引使用 SQLite 保存向量、片段和版本信息，适合当前本地单用户、小规模知识库。它与原有人工发布登记分别保存。

## API 配置

在项目根目录 `.env` 填写：

```dotenv
KP_PROVIDER=openai-compatible
KP_API_BASE=https://你的服务商/v1
KP_API_KEY=你的密钥
KP_MODEL=你的生成与审核模型
KP_EMBEDDING_MODEL=Qwen/Qwen3-Embedding-8B
```

嵌入默认复用 `KP_API_BASE` 和 `KP_API_KEY`。如使用不同服务，设置 `KP_EMBEDDING_API_BASE`、`KP_EMBEDDING_API_KEY`。嵌入地址支持服务根地址、`/v1` 或完整 `/embeddings` 地址。更改配置后重启工作台。

对于明确支持相应参数的服务，可以设置 `KP_ENABLE_THINKING=false` 关闭思考，或用 `KP_THINKING_BUDGET` 限制思考预算；留空时保持服务默认行为。不同服务并不一定接受这些扩展参数。本次使用 SiliconFlow 的 `tencent/Hy4-preview`，实际验证了关闭思考模式。

## 在页面使用

1. 打开工作台底部的“检索与问答验证”。
2. 选择正式索引，或勾选“独立测试索引”。正式索引只收录已批准的有效当前版本；测试索引额外允许待人工审核的卡片。
3. 点击“建立 / 更新索引”。页面会显示卡片数、片段数和模型名称。首次需要请求嵌入 API，相同内容后续使用缓存。
4. 输入一个实际业务问题，点击“检索验证”。需要生成回答时保留对应勾选项；只检查召回可取消勾选。
5. 展开结果查看知识正文、片段引用、内容版本和来源包。检查参数、对象、条件和例外是否与问题一致。没有依据时应说明缺少信息。

测试索引不会自动批准、发布卡片，也不会替你勾选发布后人工验收。新增或修订卡片后需要更新索引；已经退回、验收失败或版本变更的旧内容，即使尚未更新索引，也会在检索时被过滤。

## 命令行

在项目根目录执行：

```powershell
$env:PYTHONPATH="src"
.\.venv\Scripts\python.exe -B -m knowledge_pipeline --workspace .knowledge-workspace index
.\.venv\Scripts\python.exe -B -m knowledge_pipeline --workspace .knowledge-workspace search "你的问题" --answer
```

完成下面的批量生成后，可验证本地 50 张待审核卡（新克隆的仓库不自带生成卡片）：

```powershell
$env:PYTHONPATH="src"
.\.venv\Scripts\python.exe -B -m knowledge_pipeline --workspace .knowledge-workspace-benchmark50 index --sandbox
.\.venv\Scripts\python.exe -B -m knowledge_pipeline --workspace .knowledge-workspace-benchmark50 search "布尔输入从真变假时报告事件，用哪个功能块？" --sandbox --answer
.\.venv\Scripts\python.exe -B -m knowledge_pipeline --workspace .knowledge-workspace-benchmark50 serve --source-root . --port 8772
```

`--sandbox` 是单独索引文件，不影响正式索引。正式索引保存在工作区的 `retrieval.sqlite3`，测试索引为 `retrieval-sandbox.sqlite3`；生成状态仍在 `pipeline.sqlite3`，原始来源包和不可变卡片版本仍保存在工作区原目录。

## 50 张卡的可复现测试

以下命令会下载公开官方文档并调用配置的真实模型，发生 API 用量：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 tools/benchmark50_sources.py
.\.venv\Scripts\python.exe -B -X utf8 tools/benchmark50_cases.py
.\.venv\Scripts\python.exe -B -X utf8 tools/benchmark50.py generate
.\.venv\Scripts\python.exe -B -X utf8 tools/benchmark50.py evaluate --split dev
.\.venv\Scripts\python.exe -B -X utf8 tools/benchmark50.py evaluate --split heldout
```

生成阶段最多并发 4 个任务，每个任务限制 6 次调用；成功结果按卡保存，重跑会跳过已有结果。若上次调用结果不明确，会要求先核对回执，避免重复消耗。修改检索策略或回答提示后，用新的 `--label` 保存新一轮结果，不能沿用旧回答冒充重新测量。

`output/benchmark50/cases.frozen.json` 与 `cases.sha256` 固定 50 张卡的任务、100 个检索问题和 20 个无答案问题。20 张卡用于开发检查，30 张用于保留验证；生成只接收任务范围和来源，不接收问题集或标准答案。每张卡另运行一个改写问法的真实问答，加上无答案问题，共 70 个问答样本。阈值在生成前固定：Top-3 召回至少 90%、可回答问题正确率至少 85%、无答案问题拒答至少 95%。

来源快照、卡片、逐次调用回执、问题结果与向量缓存都保存在本地，并已从源码提交中忽略。下载工具只访问事先固定的官方地址，不改变正式网页导入的域名白名单与公网地址检查。重新下载得到新版本来源时，应新建测试批次，不能覆盖已冻结测试集。

检索命中率可按预设卡片 ID 计算，问答是否正确仍需逐条对照冻结的参考事实、来源及实际引用核对。`benchmark50_report.py` 仅在 `evaluations/<label>/semantic-review.json` 已记录本轮回答的核对结论和对应哈希时汇总语义成绩；它不会自动裁判答案。首次重跑不会生成该人工/代理核对文件，也不能直接得到已通过的问答结论。仓库中的指标摘要仅记录已完成的那一轮实验。

## 检索与评估的边界

当前使用余弦相似度，短卡整体入库，较长卡按段落切片并保留主题范围。按最相关片段给卡片排序，回答时展开对应的完整知识卡，减少定义、默认值与条件分离造成的信息丢失。每张卡最多展开 18,000 字符；超出时使用首个知识片段与两个最相关片段，保持上下文有界。回答最多取前三张卡，引用必须对应实际提供的卡片或片段。公式只在问题需要计算式时输出，并要求保留来源的符号与单位。

本轮问题是事先人工编写的固定测试，回答由同一配置模型生成并由代理对照官方来源和参考事实核对，未引入独立领域专家。结果说明这组数据上的可用性；不能据此保证任意领域、扫描 PDF、跨文档推理或大规模向量库的质量。导入其他检索平台后，仍需在该平台重新测量。

实现参考：[Qwen3-Embedding 官方模型说明](https://huggingface.co/Qwen/Qwen3-Embedding-8B)、[SiliconFlow Embeddings API](https://docs.siliconflow.com/cn/api-reference/embeddings/create-embeddings)、[SiliconFlow Chat API](https://docs.siliconflow.cn/docs/api/chat-completions-post)。查询按 Qwen 推荐格式添加任务指令，文档向量不添加查询指令；向量会归一化并验证维度和有限数值。
