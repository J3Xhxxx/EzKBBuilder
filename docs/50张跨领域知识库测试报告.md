# 50 张跨领域知识库测试报告

测试日期：2026-09-12。结论：**本轮小规模知识库的召回与问答已达到预设可用标准**。这不是对所有领域的准确率承诺，也不是知识卡全文的独立专家认证。

## 测试范围与模型

真实生成了 50 张中文知识库卡，覆盖 5 个领域，每个领域 10 张；以回答实际使用问题、保留条件与引用为目标。材料部分具体测试材料分子动力学仿真的命令、参数与结果解释，不涉及材料牌号性能预测。

| 领域 | 来源与内容 |
|---|---|
| 材料仿真 | [LAMMPS 官方文档](https://docs.lammps.org/units.html)：单位、边界、晶格、势参数、邻居表、时间步、弛豫、系综、应变率、原子应力。 |
| PLC 自动化 | [CODESYS Standard 官方文档](https://content.helpme-codesys.com/en/libs/Standard/Current/index.html)：TON、TOF、TP、R_TRIG、F_TRIG、CTU、CTD、CTUD、RS、SR。 |
| 数据库 | [PostgreSQL 16 官方文档](https://www.postgresql.org/docs/16/transaction-iso.html)：事务隔离、完整性约束、部分索引、多列索引。 |
| 数据处理 | [Python 3.12 官方文档](https://docs.python.org/3.12/library/csv.html)：JSON、CSV、均值、中位数、样本与总体标准差。 |
| 统计建模 | [scikit-learn 官方文档](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.StandardScaler.html)：缩放、编码、缺失填补与训练验证划分。 |

生成、审核、修复和问答模型为 `tencent/Hy4-preview`，通过项目已配置的 SiliconFlow API 实际调用；本轮 `enable_thinking=false`。嵌入模型严格使用 `Qwen/Qwen3-Embedding-8B`，实测输出 4096 维，使用归一化向量的余弦相似度。未增加重排模型。

来源均下载为本地快照，保存地址、采集时间和文本 SHA-256。使用相同 `knowledge_card` 1.1 模板，没有为不同测试题手写生成结果。

## 测试方法

生成前冻结了任务范围、100 个可回答检索问题、20 个无答案问题及参考事实。每张卡有一个明确术语问法和一个改写问法；实际问答测试使用改写问法，共 50 个，再加 20 个无答案问题。问题和标准答案没有传入生成过程，也没有作为知识内容进入索引。

20 张卡、40 个检索问题作为开发集；30 张卡、60 个检索问题作为保留验证集。无答案问题按领域分配，各阶段 10 个。无答案问题包含现场扫描周期、试样实测参数、生产表配置、真实训练成绩等，要求明确区分官方通用文档与用户现场事实。

预设门槛：Top-3 召回 ≥90%，可回答问题正确率 ≥85%，无答案问题正确拒答 ≥95%。召回按预先指定的卡片 ID 计算；正确回答须具备问题所需的关键事实、必要条件和实际引用。问答正确性由代理逐条对照参考事实及必要的官方来源核对，**不是把模型的 answerable=true 当作正确，也没有独立领域专家参与**。

## 发现的问题与修复

1. **并发第一次创建工作区会发生 SQLite 锁竞争。** 增加初始化互斥；已通过并发创建工作区的回归测试。
2. **召回卡片正确，提供给问答的片段却不完整。** 最初只提供一段时，材料边界问题遗漏了 f/s 的实际行为；扩展为两段后改善，但保留验证集的 DictReader 问题仍选中了范围和示例，遗漏正文默认值。最终改为用片段排序、回答时展开完整知识卡，保留同版本引用；超长卡采用有界回退。
3. **回答主动展开额外公式时发生负号错误。** 原子应力卡及来源均正确，但早期问答把压力求和关系的负号写错。限制无关公式展开，要求保留来源符号、变量与单位；复测回答正确说明压力×体积量纲、负号及体积归一化边界。
4. **缺少可实际操作的检索入口。** 新增嵌入接口、持久化索引与缓存、CLI `index/search`、页面“检索与问答验证”。页面显示命中正文、回答引用、版本和依据不足反馈。

生成过程中，机器审核还识别了 CODESYS TP 原文接口说明中 IN/EN 命名不一致的问题，执行一次定向修复并复审通过。另有 3 次生成 JSON 重试。所有最终卡片仍是待人工审核状态，未自动批准或发布。

| 过程记录 | 检索 Top-3 | 可回答问答 | 无答案拒答 |
|---|---:|---:|---:|
| 单片段开发集首测 | 40/40 | 19/20 | 10/10 |
| 双片段开发集复测 | 40/40 | 20/20 | 10/10 |
| 双片段保留集首次验证 | 60/60 | 28/30 | 10/10 |
| 完整知识卡上下文，全量复测 | 100/100 | 50/50 | 20/20 |

**最后一行是修复后的回归复测，不再称为未见测试。** 保留集首次验证的失败结果和原始回答仍留存。数据库部分索引回答曾有扩大“参数化条件不能证明索引谓词”限制的表述倾向，最终提示要求保留适用条件；对此类依赖查询规划条件的内容，后续仍适合加入实际 SQL 执行测试。

## 运行成本与验证

本轮生成、开发测试、保留测试与修复后全量复测共记录 **275 次成功对话响应，1,144,932 个对话 tokens**：生成 53 次、审核 51 次、修复 1 次、问答 170 次。没有记录到对话 API 超时或传输失败。嵌入阶段记录 **29 次请求，69,345 个 tokens**；其余重复内容命中本地缓存。

以上不含接口预检及少量页面交互验证请求，实际账单以服务商为准。生成至机器审核结束的单卡耗时中位数约 **17.05 秒**，P95 约 **40.94 秒**，最长 **66.30 秒**。这组耗时使用关闭思考配置，不与此前不同样本的长思考测试直接作性能倍率比较。

32 项完整回归测试通过，含安装包离线启动测试；最终上下文调整后又通过 7 项检索专项回归。页面验证覆盖正式索引无待审核内容、测试索引查询、明确结果反馈、引用展示；前端 JavaScript 语法检查通过。

## 文件与使用

公开仓库包含测试脚本、[指标摘要](benchmarks/benchmark50-summary.json)和本文。第三方来源快照、生成卡片、向量及逐次调用回执没有随源码分发。下列路径是测试运行后在本地产生的位置；新克隆的仓库不会已有这些数据：

- `output/benchmark50/cards/`：每张卡的 Markdown、JSON、审核结论、任务与调用回执。
- `.knowledge-workspace-benchmark50/`：50 张卡的生命周期数据、原始来源包、不可变版本和测试向量索引。
- `output/benchmark50/cases.frozen.json`、`cases.sha256`：冻结测试集与校验值。
- `output/benchmark50/evaluations/parent-v3/`：最终 120 条检索记录、70 条问答、逐条核对结论与指标摘要。
- `output/benchmark50/answers/` 与 `evaluations/expanded-v2/`：早期失败与修复过程证据。

完成本地批量生成后，可以用 `--workspace .knowledge-workspace-benchmark50 serve --source-root . --port 8772` 启动测试工作台。在底部“检索与问答验证”勾选独立测试索引，即可询问本轮卡片；正式索引不会收录这些待审核卡。

配置、启动、检索命令和重跑方法见 [本地检索与批量验收](本地检索与批量验收.md)。需自行填写 API；`.env.example` 默认使用离线模拟，并给出本轮嵌入模型名称。重新运行会产生 API 用量，远端模型与来源更新可能改变成绩；问答语义结论需要再次逐条核对，不能直接复用本文分数。

仍需保留的边界：本轮是 50 张、官方文本来源、明确单元范围的小规模实验；尚未验证扫描件、多模态表格、数万张卡、独立专家盲测和其他知识平台的召回。对高风险参数或重要生产决策继续做人工核对，当前人工审核流程保持有效。
