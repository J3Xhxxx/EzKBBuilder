# EzKBBuilder 架构说明

## 知识库知识单元与生产流程

卡片内容结构由 profile 定义，生产流程由核心服务统一管理。默认 `knowledge_card` 面向知识库检索与问答，围绕单一知识主题，要求可独立理解、可核对来源、能支持问题回答的知识正文。当前模板版本为 `1.1`，必填段落为主题与范围、知识正文，沿用 `summary`、`key_points` 键。解释、示例、应用及适用边界是选填内容；概念、事实、方法与问答可以使用同一结构，不强制六节、科普式简短字数或行业流程。

```text
KnowledgeSpec + Sources
  → SourceBundle（来源快照与哈希）
  → Provider.generate
  → 本地结构、引用和版本校验
  → Provider.audit
  → 最多一次 Repair → 完整重审
  → Human Review（绑定当前内容哈希）
  → Markdown / JSON / ZIP
  → 人工发布登记
  → 来源支撑 / 主题相关 / 表达清楚 / 检索可用验收
```

生成、审计与人工审核是生产质量环节，不是要求写入卡片正文的章节。

## 模块职责

- `core/`：数据对象、状态机、结构校验、确定性渲染和流程编排。
- `providers/`：直接模型 API、FastGPT App 和离线模拟适配器。
- `sources/`：本地文本、受控网页、规范化和来源快照。
- `storage/`：SQLite 状态、事件、任务、修复预算、审核、发布与验收记录。
- `profiles/`：段落、Prompt、修复次数和验收项的数据定义。
- `web/`：HTTP 与工作台展示，业务动作调用 `PipelineService`。
- `retrieval.py`：嵌入 API、向量校验、持久化索引与缓存、卡片排序和带引用问答。

## 卡片结构与输出合同

`KnowledgeSpec` 描述项目内编号、标题、模板、受众、目标和可选元数据。省略模板时选择 `knowledge_card`。`metadata.domain`、`card_type`、`tags` 可帮助描述知识，但不作为事实证据，也不要求任何行业编号。

每个模板段落声明 `required`。默认必填段落是 `summary`、`key_points`，选填段落是 `explanation`、`examples`、`application`、`boundaries`。生成器应省略没有合适内容的选填键；本地校验会把选填空字符串视为省略，拒绝空的必填段落、未知段落和非字符串正文。Markdown 只渲染实际保留的段落。

模型审计检查来源支撑、主题相关和表达质量，并检查知识单元是否自包含、主体是否明确、来源提供的版本与适用条件是否完整，不得因未采用选填段落判失败。会改变结论的条件与例外应紧邻相应事实，不能只依赖独立边界段落，以降低下游切片丢失条件的风险。定向修复只能处理审计指定段落；选填目标返回空字符串可删除该段落，必填目标仍必须有正文。修复候选必须重新通过完整校验和审计。

## 对象与版本绑定

`SourceBundle` 保留来源原始字节哈希、规范化文本哈希、采集时间与整体哈希。`KnowledgeDocument` 绑定模板版本、Schema 版本、来源包、模型追踪和生成代次。

`AuditReport`、`ReviewDecision`、`PublicationRecord`、`EvaluationResult` 都记录当前文档哈希。旧版本审核、缺少当前导出包的发布登记、没有当前发布记录的验收都会被拒绝。验收失败必须记录对应原因。

## 状态与恢复

主要状态包括 `READY`、`GENERATING`、`AUDITING`、`REPAIRING`、`PENDING_REVIEW`、`APPROVED`、`PENDING_PUBLICATION`、`PUBLISHED`、`EVALUATION_PASSED`、`EVALUATION_FAILED`、`STOPPED` 和 `INTERRUPTED`。

状态转换写入事件表，Web 定时读取真实状态。文档级锁记录进程与任务标识，防止同一文档并发生成；启动时只回收没有存活进程持有的任务和锁。远端超时或传输中断记为 `UNCERTAIN`，表示远端可能已执行，但本地没有收到确定结果。

人工退回后可更新同一模板下的任务描述与来源，再生成新版本。每个版本保留当时的任务描述、来源哈希、Prompt 哈希与父版本哈希。

历史卡片使用保存于版本中的模板信息展示正文。即使原模板已移除，也能读取原卡；重新导出或验收仍需要对应模板，不能把旧版本偷偷套用新格式。

## Provider 与来源边界

Generate 输出卡片段落，Audit 只输出结论和问题，Repair 只修改指定段落。所有 Provider 输出均经过本地 JSON、段落、引用及版本检查。来源正文作为数据处理，不能改变输出格式或审核规则。

直接 API 使用仓库内版本化 Prompt。FastGPT App 可能在远端保存 Prompt，使用者需同步所选模板的结构与行为约定。`mock` 仅以来源摘录演示结构和状态，不执行真实模型归纳或事实审计，不能用于衡量内容质量。

## 模板扩展

`knowledge_card` 是跨领域默认模板；`product_docs` 是可选的固定产品使用文档模板。工作台默认使用星桥图书室业务 FAQ；语言学习概念与日常整理方法仍是附加示例，使用相同的 `knowledge_card`，只改变任务和来源。随 wheel 分发的最小离线演示保持独立。

新增领域通常不需要增加模板。需要不同固定章节时才增加 profile，用 YAML 与文本 Prompt 声明，不允许从配置任意导入 Python。未来可以增加 SOP 模板；若要执行动作，需要独立的授权与执行模块，知识生成服务本身不执行卡片中的内容。

## 本地检索与问答

短卡整体嵌入，长卡按段落切片，使用最相关片段给卡片排序；回答时展开对应的完整知识卡（每卡最多18,000字符），超长卡回退到核心片段与最相关片段。查询采用 Qwen 的任务指令格式，检查向量数量、索引、维度、有限数值与非零范数后归一化，以余弦相似度检索。

SQLite 正式与测试索引分文件保存。正式索引收录已批准的有效当前版本，测试索引还可收录待审核版本；查询时再次核验当前版本及生命周期状态，过滤已退回、验收失败或过期卡。回答引用必须属于本次实际提供的上下文。这些结构检查不能替代语义核对，也不会自动记录人工审核或发布后验收结果。

## 当前限制

- 本地单用户运行，不含账户、多租户或分布式队列。
- 本地来源支持 UTF-8 Markdown/TXT；未接入 PDF、Office 和复杂网页解析。
- 网页来源要求精确域名白名单。
- 发布依赖人工完成后登记，不会自动写入外部知识平台；本地向量索引使用全量余弦计算，未面向大规模向量库优化。
- 发布后验收由人工执行；已完成50张卡的本地检索测试，外部平台的召回与回答仍需在目标平台确认。
- 本地引用检查保证引用结构与来源 ID 有效，不能单独证明语义与事实准确；仍依赖模型审计及人工审核。
